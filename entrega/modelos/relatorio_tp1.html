1. Tema e objetivos

Gambiarra é uma linguagem pequena com o vocabulário do "conserto improvisado": o programa é uma gambiarra, cada variável é um remendo, e os valores lógicos são firme (verdadeiro) e quebrado (falso). O transpilador, escrito em Python, traduz um programa .gam para C (a linguagem destino de referência do enunciado), que depois é compilado com o gcc.

Objetivos: formalizar o léxico (alfabeto Σ, tokens e expressões regulares) e a sintaxe (GLC em EBNF); implementar à mão o analisador léxico e o parser por descida recursiva, com construção da AST; fazer uma análise semântica com tabela de símbolos, escopo e tipos; e gerar C que preserva o comportamento do programa.

2. Três decisões próprias de projeto

1. Declaração sem tipo escrito, com tipo deduzido do valor. Na BIRL-Lite o tipo vem antes do nome (MONSTRO x = 3;) e o valor é opcional. Na Gambiarra escreve-se remendo x = 3;: o valor é obrigatório e a variável recebe o tipo dele (3 → inteiro, 2.5 → real, firme → lógico). A tipagem continua estática: o tipo é fixado na declaração e conferido pela semântica (regras R7 e R12). Justificativa: há menos palavras reservadas, nenhuma variável existe sem valor (no C não sobra variável sem inicialização) e o tipo nunca contradiz o valor inicial.

2. Blocos delimitados por chaves obrigatórias. A BIRL-Lite fecha programa, if e while com a mesma palavra (BIRL). Na Gambiarra, todo bloco (programa, se, senao, enquanto) é delimitado por { }, sempre. Justificativa: fica visível onde cada bloco começa e termina, e o fechamento explícito elimina a ambiguidade do "else pendurado": cada senao vem logo depois do } do seu se.

3. Saída com vários itens e quebra de linha automática. A BIRL-Lite mostra um item por comando e exige \n no texto. Na Gambiarra, mostra("total: ", x, " de ", y); mistura textos e expressões separados por vírgula, e cada mostra termina a linha. Justificativa: ninguém esquece o \n, e o gerador monta um único printf, escolhendo o formato de cada item pelo tipo calculado na semântica (%d, %g, firme/quebrado).

Outras diferenças em relação à BIRL-Lite: tipo lógico, operadores lógicos && || ! na gramática, operador %, menos unário e comentários de linha e de bloco.

3. Especificação léxica

3.1 Alfabeto Σ

Σ = { a–z, A–Z (sem acento) } ∪ { 0–9 } ∪ { _ " . , ; ( ) { } + - * / % = ! < > & | \ } ∪ { espaço, tabulação, quebra de linha }. Dentro de um texto ou de um comentário, qualquer caractere é aceito (inclusive acentos). Um programa é uma palavra de Σ*. Cada categoria de token é uma linguagem regular sobre Σ, descrita por uma expressão regular (Menezes, 2011, cap. 3), e o léxico reconhece essas palavras dentro do programa. Um símbolo fora de Σ (ex.: @, #, ç) é erro léxico.

3.3 Como o léxico resolve os conflitos

O léxico (lexico.py) tem uma tabela de regras (nome, expressão regular), testada em ordem a cada posição do texto. A primeira que casa ganha, e o lexema vira token (ou é ignorado, ou vira erro).

  • Palavra reservada × identificador: se casa com a ER de ID; depois o léxico consulta a tabela PALAVRAS_RESERVADAS e, se o lexema está nela, o token vira SE. Por isso sera continua sendo identificador.
  • Maior casamento (longest match): == != >= <= && || vêm antes de = ! > <. Sem isso, == viraria dois tokens =. NUM_REAL também vem antes de NUM_INT.
  • Fim do número: NUM_INT e NUM_REAL exigem que o número acabe ali ((?![\w.])). Sem isso, 2abc viraria NUM(2) ID(abc) e 3.4.5 viraria NUM(3.4) + resto.
  • Posição: cada token guarda linha e coluna. A cada lexema, a coluna avança o tamanho dele; se houver quebra de linha, a linha avança e a coluna recomeça.
  • Erros: regras de erro (número malformado, identificador com acento, texto sem fechar, escape inválido, comentário sem fechar e o "pega-tudo" .) registram linha, coluna e lexema e a leitura continua. Se houver erro léxico, o parser não roda.

4. Especificação sintática: G = (V, T, P, S)

V = { Programa, Bloco, Instrucao, Declaracao, Atribuicao, Leitura, Escrita, Item, Condicional, Repeticao, Expressao, ExprE, ExprRel, OpRel, ExprAdit, Termo, Unario, Fator }
T = { gambiarra, remendo, mostra, pega, se, senao, enquanto, firme, quebrado, id, num_int, num_real, texto, + - * / % = == != > >= < <= && || ! ( ) { } ; , }
S = Programa
P (EBNF: { } zero ou mais, [ ] opcional, ( | ) agrupamento, "x" terminal):

<Programa>    ::= "gambiarra" <Bloco>
<Bloco>       ::= "{" { <Instrucao> } "}"
<Instrucao>   ::= <Declaracao> | <Atribuicao> | <Leitura> | <Escrita>
                | <Condicional> | <Repeticao>
<Declaracao>  ::= "remendo" id "=" <Expressao> ";"
<Atribuicao>  ::= id "=" <Expressao> ";"
<Leitura>     ::= "pega" "(" id ")" ";"
<Escrita>     ::= "mostra" "(" <Item> { "," <Item> } ")" ";"
<Item>        ::= texto | <Expressao>
<Condicional> ::= "se" "(" <Expressao> ")" <Bloco> [ "senao" <Bloco> ]
<Repeticao>   ::= "enquanto" "(" <Expressao> ")" <Bloco>
<Expressao>   ::= <ExprE> { "||" <ExprE> }
<ExprE>       ::= <ExprRel> { "&&" <ExprRel> }
<ExprRel>     ::= <ExprAdit> [ <OpRel> <ExprAdit> ]
<OpRel>       ::= "==" | "!=" | ">" | ">=" | "<" | "<="
<ExprAdit>    ::= <Termo> { ( "+" | "-" ) <Termo> }
<Termo>       ::= <Unario> { ( "*" | "/" | "%" ) <Unario> }
<Unario>      ::= ( "!" | "-" ) <Unario> | <Fator>
<Fator>       ::= num_int | num_real | "firme" | "quebrado" | id | "(" <Expressao> ")"

4.1 Precedência, associatividade e ausência de ambiguidade

Cada nível de precedência é uma variável da gramática: quanto mais fraco o operador, mais perto da raiz fica a regra dele. Os parênteses (em <Fator>) são o único jeito de "furar" os níveis.

NívelOperadoresVariávelAssociatividade
1 (mais fraco)||Expressaoesquerda
2&&ExprEesquerda
3== != > >= < <=ExprRelnão associativo (a < b < c é erro sintático)
4+ -ExprAditesquerda (10 - 3 - 2 = 5)
5* / %Termoesquerda
6! e - unáriosUnariodireita (- -3 = 3)
7 (mais forte)número, variável, firme, quebrado, ( )Fator—

É a mesma ordem do C, por isso o C gerado se comporta igual. Sem recursão à esquerda: a forma A → A op B (que associa à esquerda, mas faria a descida recursiva chamar a si mesma sem consumir token) foi escrita como A → B { op B }, que no parser é um while que junta cada termo novo à esquerda da árvore já montada. LL(1): as alternativas de <Instrucao> começam com tokens diferentes (remendo, id, pega, mostra, se, enquanto), e em <Item> o token texto não pertence a PRIMEIROS(<Expressao>). Por isso basta espiar um token para escolher a regra.

O * ficou dentro de um <Termo>, mais fundo que o +, então é calculado primeiro: 2 + (3 * 4) = 14. A AST guarda só a estrutura ((2 + (3 * 4))), sem ;, chaves ou variáveis intermediárias. A precedência está na própria árvore, e o gerador não "conserta" nada.

5. Analisador sintático e AST

parser.py implementa um parser por descida recursiva: cada regra da EBNF é uma função (programa(), bloco(), declaracao(), ..., fator()). Na EBNF, <Nome> vira uma chamada de função, { } vira while, [ ] vira if e um terminal vira consome(TIPO). As duas ferramentas básicas são proximo(), que espia o tipo do token atual, e consome(tipo), que confere o token e avança. Cada função devolve um nó da AST (ast_nos.py: Declaracao, Atribuicao, Leitura, Escrita, Se, Enquanto, Binario, Unario, literais e Variavel), com linha e coluna. O parser também registra as regras chamadas e os tokens consumidos, para imprimir a árvore de derivação (--derivacao).

Erro sintático: o parser para no primeiro erro e informa linha, coluna, token encontrado e o que era esperado. Um ; esquecido é apontado no fim da linha onde ele falta, e não no token da linha seguinte.

6. Análise semântica

semantico.py percorre a AST depois do parser. Ele mantém a tabela de símbolos (nome → tipo, linha da declaração, nome no C) como uma pilha de escopos: cada bloco empilha um escopo ao entrar e o desempilha ao sair. Declarar olha só o topo da pilha; procurar vai do topo para baixo. Ele calcula o tipo de cada expressão de baixo para cima (literal pelo formato, variável pela tabela, operação pelas regras abaixo) e lista todos os erros. Com qualquer erro, o C não é gerado.

RegraDescriçãoExemplo de violação
R1variável só pode ser usada depois de declaradamostra(pontos); sem declarar
R2não pode declarar duas vezes no mesmo escoporemendo x = 1; remendo x = 2;
R3escopo por bloco: se, senao e enquanto têm o seuusar fora do se uma variável declarada dentro dele
R4sombreamento permitido: um bloco interno pode redeclarar um nome de fora— (é válido)
R5+ - * / só com números; inteiro com inteiro dá inteiro; com um real, dá real. % só com inteirospeso % 2 com peso real
R6> >= < <= só com números; == != entre números ou entre lógicos; && || ! só com lógicos; - unário só com númerosligado + 1
R7atribuição: real ← inteiro vale (promoção); inteiro ← real não; número ↔ lógico nãovidas = 2.5; com vidas inteiro
R8/ entre inteiros é divisão inteira (7 / 2 = 3), como no C—
R9na declaração, o valor é conferido antes de o nome existirremendo x = x + 1; sem outro x
R10a condição de se/enquanto tem que ser lógicase (vidas) { }
R11pega só lê variável inteira ou real, já declaradapega(ligado); com ligado lógico

Por que separar da sintaxe: mostra(x); e mostra(y); viram a mesma sequência de tokens (mostra ( id ) ;). O parser não tem como saber se y foi declarada; quem sabe é a tabela de símbolos. "Declarar antes de usar" depende de contexto.

7. Geração de código C

gerador.py só roda se léxico, parser e semântica passaram. Ele percorre a AST (não faz substituição de texto): cada tipo de nó tem uma função que escreve o C equivalente. Os tipos viram inteiro → int, real → float (o scanf usa %f) e lógico → int (0/1). As variáveis ganham o prefixo v_, para um nome como int não quebrar o C. Toda operação ganha parênteses. mostra vira um único printf: %d para inteiro, %g para real, %s para texto e para lógico (impresso como firme/quebrado), com \n no fim. pega vira scanf com %d ou %f.

Sombreamento: dentro de um bloco, remendo x = x + 1; deve ler o x de fora (R9). No C, int v_x = v_x + 1; leria o x novo, ainda sem valor. Por isso a semântica dá à variável de dentro outro nome (v_x_2), e o comportamento é preservado (teste 07).

10. Como executar

Pré-requisitos: Python 3.10+ (só a biblioteca padrão) e gcc.

python transpilador.py programa.gam                  (gera gerados/programa.c)
python transpilador.py programa.gam --executar       (gera, compila com gcc e roda)
python transpilador.py programa.gam --tokens --derivacao --ast --c
python rodar_testes.py                               (suíte de testes)

Organização: tokens.py e erros.py (base), lexico.py (1), parser.py + ast_nos.py (2), semantico.py (3), gerador.py (4) e transpilador.py (liga as estações). Detalhes no README.md.
